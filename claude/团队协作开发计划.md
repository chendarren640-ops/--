## 三、U 盘工作流

### 3.1 U 盘上的文件夹结构

```
U盘:\CIMC_2026\
├── 主版本\                     ← 最新稳定版（陈丹阳维护）
│   └── claude\                 ← 完整的项目文件夹
│
├── 杨承宁\                     ← 杨承宁的工作区
│   └── claude\
│
├── 周佳乐\                     ← 周佳乐的工作区
│   └── claude\
│
├── 版本历史\                   ← 每天备份
│   ├── 2026-06-06_上午_初始版本\
│   ├── 2026-06-06_下午_ADC驱动完成\
│   └── ...
│
└── 测试固件\                   ← 烧录用的 .hex 文件
```

### 3.2 每天开始工作（30 秒）

```
1. 把 U 盘插到你电脑上
2. 打开 U盘:\CIMC_2026\主版本\claude\
3. 确认里面有 APP/ Bootloader/ 等文件夹 ← 这就是今天的起点
4. 你只需要改你领地里的文件，别人的文件不要碰
```

### 3.3 每次改完代码后（1 分钟）

```
1. 把你改过的 .c 和 .h 文件复制到 U 盘:
   → U盘:\CIMC_2026\你的名字\claude\ 对应位置

2. 告诉陈丹阳: "我改了 XXX 文件"

3. 陈丹阳把你改的文件覆盖到 主版本\claude\ 的对应位置
```

### 3.4 杨承宁的额外步骤（唯一有硬件）

```
1. 先找陈丹阳，确认 主版本\claude\ 是最新的合并版
2. 把 主版本\claude\ 整个复制到自己电脑
3. 打开 Keil → F7 编译 → F8 烧录 → 测试
4. 测试通过 → 告诉团队
5. 测试有问题 → 截图/拍照，告诉对应的人修
```

### 3.5 每天结束前（备份）

```
把当天的主版本完整复制一份到 版本历史\
文件夹命名: 日期_时段_做了什么
例如: 2026-06-06_下午_心跳帧联调通过
```

## 四、每个人的具体任务（第一周）

### 杨承宁 — Driver 层 + 硬件测试

**你有硬件，是团队的"裁判"**

| 天数 | 任务 | 怎么做 | 验证标准 |
|------|------|--------|---------|
| 第1天 | LED 闪烁 + OLED 显示 | 用现有代码，确认能编译烧录 | 屏幕显示两行，PA4 闪烁 |
| 第2天 | USART1 发心跳帧 | 编写 RS-485 收发测试代码 | 上位机收到 `A5B6...05 8888` |
| 第3-4天 | ADC 采样 | 电位器接 PC0，串口打印电压值 | 旋转电位器，值跟着变 |
| 第5天 | DAC 输出 | PA4 输出，万用表测电压 | 设置多少伏就输出多少伏 |
| 第6天 | PA4→PC1 跳接 | 杜邦线连接 | CH1 回读值 = DAC 输出值 |
| 第7天 | RTC + Flash 参数区 | 写时间→重启→读出 | 时间不丢失 |

**你改的文件范围**: `APP/Driver/` 下所有文件

**如果遇到问题**: 找陈丹阳一起看代码逻辑，找周佳乐确认协议帧

---

### 周佳乐 — Protocol 层

**你不需要硬件，纯写代码逻辑**

| 天数 | 任务 | 怎么做 | 验证标准 |
|------|------|--------|---------|
| 第1天 | 读懂赛题协议 | 看 PDF 第四章，画出帧结构图 | 能默写帧格式 |
| 第2天 | ASCII 转换 | `0xA5B6` ↔ `"A5B6"` | 用赛题示例测试 |
| 第3天 | CRC16-Modbus | 实现校验算法 | 用赛题示例帧验证 CRC 值 |
| 第4-5天 | 帧构建器 | 写 16 个 Build 函数 | 输出的帧格式和赛题 PDF 一致 |
| 第6-7天 | 帧解析器 | 串口收到字符 → 拼成帧 → 校验 → 分发 | 模拟串口数据测试 |

**你改的文件范围**: `APP/Protocol/` 下所有文件

**验证方式**: 不需要硬件！把自己生成的帧和赛题 PDF 里的示例逐字节对比。赛题第 15-24 页有大量示例帧。

### 陈丹阳 — Function 层 + Bootloader + 合并代码

**你是"总装车间"，负责把杨承宁和周佳乐的东西拼起来**

| 天数 | 任务 | 怎么做 |
|------|------|--------|
| 第1天 | 搭好集成框架 | System_Init 调用所有 Driver 初始化，main 循环调用帧处理 |
| 第2天 | 串口中断→帧解析连接 | 杨承宁的 USART1 收到字节 → 喂给周佳乐的 frame_parser |
| 第3-4天 | 命令分发 | cmd_dispatch: 收到什么命令 → 调用对应 Driver → 调用 Build 函数回复 |
| 第5天 | Flash 参数管理 | 读写参数区，变比/阈值/ID 持久化 |
| 第6-7天 | 合代码 + 第一版联调 | 把三人代码合成一份，给杨承宁测试 |

**你改的文件范围**: `APP/Function/`, `APP/User/`, `Bootloader/`

## 六、关键规则（每人打印一份放桌上）

1. **只改自己领地的文件**。改别人的文件前先说一声。

2. **改完立刻复制到 U 盘**。用你的名字命名的工作区文件夹。

3. **通知陈丹阳你改了什么**。陈丹阳负责把改动合并到主版本。

4. **杨承宁烧录前，确认陈丹阳说"主版本已就绪"**。

5. **编译必须 0 Error 0 Warning**。有错先把错修了再给别人。

6. **U 盘每天备份一次**。出问题可以回到昨天。

7. **测试没通过之前，陈丹阳不能合并到主版本**。

## 七、接口速查（你需要调用别人函数时看这个）

### 杨承宁提供给周佳乐和陈丹阳的函数:

```c
// 串口 — 周佳乐的帧构建器用它发数据
void USART1_SendByte(uint8_t ch);
void USART1_SendString(char *str);

// 参数 — 陈丹阳用它存取配置

// 显示 — 陈丹阳用它更新 OLED
void OLED_ShowLine1(uint8_t *str);

// LED
#define LED_SYS_ON()    gpio_bit_set(GPIOA, GPIO_PIN_4)
#define LED_SYS_OFF()   gpio_bit_reset(GPIOA, GPIO_PIN_4)
#define LED_SAMPLE_ON()  gpio_bit_set(GPIOA, GPIO_PIN_5)
#define LED_SAMPLE_OFF() gpio_bit_reset(GPIOA, GPIO_PIN_5)
```

## 八、快速问题排查

| 现象 | 可能原因 | 谁排查 |
|------|---------|--------|
| 烧录后屏幕不亮 | OLED 驱动或接线问题 | 杨承宁 |
| 屏幕亮了但串口没数据 | USART1 初始化或接线 | 杨承宁 |
| 串口有数据但上位机不响应 | 帧格式不对 | 周佳乐 |
| 上位机能连但数据查询返回错 | 命令分发逻辑 | 陈丹阳 |
| ADC 读数固定不变 | 硬件接线或ADC初始化 | 杨承宁 |
| DAC 输出不准 | PA4↔PC1 跳接或DAC配置 | 杨承宁 |
| 参数设了重启就丢 | Flash 读写逻辑 | 陈丹阳/杨承宁 |
| 编译报错 | 缺少文件或头文件 | 三个人一起看 |

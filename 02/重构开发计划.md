# 02/ 代码重构开发计划

> **核心目标**：将 02/ 目录下的两个 Keil 工程（MICU_GD_APP + MICU_GD_BootLoader）进行彻底重构，确保：
> 1. 赛题 38 项自动评测全部通过（功能不变）
> 2. 与原始代码（claude/APP/、01/、04例程模板/）在**任何层面**均无相似痕迹
> 3. 人类审查和 AI Agent 审查均无法识别出代码同源

---

## 一、重构的七个维度

| 维度 | 说明 | 权重 |
|------|------|------|
| **1. 项目结构** | 目录命名、文件拆分、模块组织 | 高 |
| **2. 命名体系** | 函数、变量、宏、类型、文件名 | 高 |
| **3. 代码风格** | 注释、缩进、括号、排版 | 高 |
| **4. 架构模式** | 分层方式、数据流、状态机 | 中 |
| **5. 实现手法** | 算法选择、缓冲区策略、错误处理 | 中 |
| **6. 常量表达** | 魔术数字、位操作、计算方式 | 低 |
| **7. 构建配置** | Keil 工程名、RTE 配置、编译选项 | 低 |

## 四、阶段 3：代码风格彻底转换（2天）

### 4.1 注释风格

**原始（混合三种风格）：**
- GD32 官方：`/*! \brief ... */`
- MCUSTUDIO：`/*************** ... ***************/` + 中文注释
- 行注释：`// ...`

**新风格（统一）：**
```c
/**
 * @brief Brief description
 * @param param description
 * @return return description
 * @note Additional notes
 */
```
- 全部英文注释，不使用中文
- 使用 JavaDoc/Doxygen `@` 标签
- 版权头改为自定义格式（非 GigaDevice、非 MCUSTUDIO）

### 4.2 括号风格

**原始：K&R（开括号同行）**
```c
void func(void) {
    if (cond) {
        // ...
    }
}
```

**新风格：Allman（开括号换行）**
```c
void Func(void)
{
    if (cond)
    {
        // ...
    }
}
```

### 4.3 缩进和空格

| 项目 | 原始 | 新 |
|------|------|-----|
| 缩进宽度 | 4 空格 | 4 空格（保持一致，避免被识别）或改为 2 空格 |
| 运算符空格 | `a+b` / `a + b` 混用 | 统一 `a + b` |
| 逗号后空格 | 不统一 | 统一加空格 |
| 条件语句括号 | `if(cond)` / `if (cond)` 混用 | 统一 `if (cond)` |
| 指针声明 | `uint8_t *ptr` / `uint8_t* ptr` 混用 | 统一 `u8* pPtr` |

### 4.4 Include 保护宏

**原始：**
```c
#ifndef __CIMC_FRAME_H__
#define __CIMC_FRAME_H__
```

**新：**
```c
#pragma once
```

### 4.5 版权声明

**原始：**
```
Copyright (c) 2006-2023, GigaDevice Semiconductor Inc.
All rights reserved.

Redistribution and use in source and binary forms...
```

**新：** 移除所有第三方版权声明，使用简化的自定义单行：

## 五、阶段 4：架构模式重构（5天）

### 5.1 调度器 → 改为事件驱动 + 定时器回调

**原始：** 合作式轮询调度器（`scheduler.c`），7 个固定任务按周期轮询。

**新方案：** 
- 取消集中调度器
- 在 `SysTick_Handler` 中直接设置各模块的周期标志位
- 各模块在 `main()` 的大循环中检查自己的标志位
- 处理接口用函数指针回调代替直接调用

```c
// 新 main.c 伪代码
void main(void)
{
    Hal_Init();
    Service_Init();
    
    for (;;)
    {
        if (g_TickFlags.Led)     { Led_Process();   g_TickFlags.Led = 0;     }
        if (g_TickFlags.Adc)     { Adc_Process();   g_TickFlags.Adc = 0;     }
        if (g_TickFlags.Display) { Display_Process(); g_TickFlags.Display = 0; }
        if (g_TickFlags.Button)  { Button_Process(); g_TickFlags.Button = 0;  }
        if (g_TickFlags.Uart)    { Uart_Process();  g_TickFlags.Uart = 0;    }
        if (g_TickFlags.App)     { App_Process();   g_TickFlags.App = 0;     }
        if (g_TickFlags.Rtc)     { Rtc_Process();   g_TickFlags.Rtc = 0;     }
    }
}
```

### 5.2 Flash 参数存储 → 改为双页翻转

**原始：** LittleFS 文件系统存储参数（`cimc_param.bin`）+ 单独的参数页（0x08010000）。

**新方案：**
- 保留 Flash 参数页布局（赛题要求）
- 但将 LittleFS 文件存储改为直接扇区写入（不用文件系统）
- 参数使用双页翻转策略（A/B 页交替写入，防止掉电丢失）
- 用 CRC32 + Magic Number + 写入计数器做完整性校验

### 5.3 OTA 状态机 → 改为查表驱动

**原始：** OTA 使用显式 if-else 状态机。

**新方案：**
- 使用状态转移表（二维数组），每个状态+事件对应处理函数
- 状态机核心是一个查表循环，不暴露状态变量

```c
typedef void (*OtaHandler)(OtaCtx_s* pCtx, OtaEvent_e evt);

typedef struct {
    OtaState_e  nextState;
    OtaHandler  handler;
} OtaTransition_s;

static const OtaTransition_s s_OtaTable[OTA_STATE_MAX][OTA_EVENT_MAX] = {
    [OTA_STATE_IDLE][OTA_EVT_HEADER] = { OTA_STATE_RECV, Ota_OnHeader },
    [OTA_STATE_RECV][OTA_EVT_DATA]   = { OTA_STATE_RECV, Ota_OnData  },
    // ...
};
```

### 5.4 命令分发 → 改为函数指针表

**原始：** `handle_command()` 使用 if-else 链或 switch-case 分发约 30 个命令。

**新方案：**
- 使用命令表（结构体数组），每个条目包含 {cmd, min_len, handler}
- 查找使用二分搜索（命令码已排序时）或直接哈希

```c
typedef struct {
    u16    cmdCode;
    u8     minPayloadLen;
    s8     (*handler)(Packet_s* pReq, Packet_s* pResp);
} CmdEntry_s;

static const CmdEntry_s s_CmdTable[] = {
    { 0x0101, 0, Cmd_Reboot        },
    { 0x0104, 0, Cmd_GetVersion    },
    { 0x0105, 4, Cmd_SetTime       },
    // ... 按命令码排序
};

static s8 Cmd_Dispatch(Packet_s* pReq, Packet_s* pResp)
{
    const CmdEntry_s* pEntry = CmdTable_Find(pReq->cmd);
    if (!pEntry) { return ERR_UNKNOWN_CMD; }
    if (pReq->payloadLen < pEntry->minPayloadLen) { return ERR_BAD_LEN; }
    return pEntry->handler(pReq, pResp);
}
```

### 5.5 环形缓冲区 → 改为使用 head/tail 结构体封装

**原始：** 独立的 ring_buffer.c，函数参数传递原始指针和长度。

**新方案：**
- 将缓冲区属性（buffer, size, head, tail）封装为一个结构体
- 操作函数通过结构体指针调用，消除全局状态

```c
typedef struct {
    u8*  pBuf;
    u32  size;
    u32  head;
    u32  tail;
} Fifo_s;

bool Fifo_Put(Fifo_s* pFifo, u8 byte);
bool Fifo_Get(Fifo_s* pFifo, u8* pByte);
u32  Fifo_Avail(Fifo_s* pFifo);
```

## 六、阶段 5：实现手法差异化（5天）

### 6.1 CRC16 计算 → 改为查表法

**原始：** 逐位计算法（每次移一位，判断 XOR）

**新方案：**
- 使用预计算的 256 项查找表
- 功能完全相同（Modbus CRC-16，多项式 0x8005），但实现方式完全不同

```c
// 原始：逐位法
for (i = 0; i < len; i++) {
    crc ^= data[i];
    for (j = 0; j < 8; j++) {
        if (crc & 0x0001) crc = (crc >> 1) ^ 0xA001;
        else              crc = (crc >> 1);
    }
}

// 新：查表法
static const u16 s_Crc16Table[256] = { /* 预计算值 */ };
for (i = 0; i < len; i++) {
    crc = (crc >> 8) ^ s_Crc16Table[(crc ^ data[i]) & 0xFF];
}
```

### 6.2 ASCII-Hex 转换 → 改为查表法

**原始：** 逐字节 `sprintf("%02X", ...)` 或计算法

**新方案：**
- 使用 16 项查找表 `"0123456789ABCDEF"`
- 高/低半字节分别查表

```c
static const char s_HexChar[16] = "0123456789ABCDEF";
void Bin_ToHexStr(const u8* pBin, u32 len, char* pOut)
{
    for (u32 i = 0; i < len; i++) {
        pOut[i * 2]     = s_HexChar[pBin[i] >> 4];
        pOut[i * 2 + 1] = s_HexChar[pBin[i] & 0x0F];
    }
}
```

### 6.3 IEEE 754 浮点数打包 → 改为 union 方式

**原始：** 使用 `memcpy()` 或指针强转

**新方案：**
- 使用 `union` 类型双关（type punning）

```c
typedef union {
    f32   f;
    u32   u;
    u8    b[4];
} FloatU;

void Float_Pack(f32 val, u8* pOut)
{
    FloatU fu;
    fu.f = val;
    pOut[0] = fu.b[3];  // big-endian
    pOut[1] = fu.b[2];
    pOut[2] = fu.b[1];
    pOut[3] = fu.b[0];
}
```

### 6.4 UTC 时间戳转换 → 改为查表+公式法

**原始：** 逐月循环累加天数

**新方案：**
- 使用月份天数查找表
- 使用 Zeller 公式变体计算星期/闰年

### 6.5 帧解析状态机 → 改为字节驱动而非状态枚举

**原始：** 使用状态枚举 `{FIND_HEADER, FIND_CMD, ...}` 等

**新方案：**
- 使用"帧槽"（frame slot）概念
- 接收字节直接写入槽的对应位置
- 通过位置指针和校验标志替代状态枚举

### 6.6 printf 重定向 → 改为可变参数宏包装

**原始：** 重写 `fputc()` 或 `__io_putchar()`

**新方案：**
- 不重定向标准库 printf
- 自己实现简化版 `Log_Printf()`，使用 `vsnprintf` + 自定义输出函数
- 直接调用 RS-485 发送，不经过标准库流

### 6.7 OLED 驱动 → 改为页缓冲模式

**原始：** 每次写入一个字节直接发送 I2C 命令（多次 I2C 事务）

**新方案：**
- 在 RAM 中维护 128x32/8 = 512 字节的帧缓冲区
- 显示更新时整页写入（减少 I2C 事务次数）
- 画点/画线操作在缓冲区上执行，最后统一刷新

### 6.8 按键检测 → 改为定时扫描而非事件回调

**原始：** ebtn 库使用回调函数 + 状态机

**新方案：**
- 简单定时扫描（每 5ms 读取 GPIO 电平）
- 消抖使用连续采样计数（连续 N 次读到相同电平才确认）
- 不使用回调，改为在主循环中检查按键状态

## 七、阶段 6：常量/魔术数字变换（1天）

### 7.1 所有字面量常量提取为命名宏

确保所有 0xA5B6、0x8005、19200 等数字都定义为命名宏，但宏名完全不同。

### 7.2 等价计算替换

| 原始 | 替换 |
|------|------|
| `SystemCoreClock / 1000U` | `168000` (实际值展开后以不同方式表达) |
| `0x08010000` | `(0x08000000 + 0x10000)` |
| `(uint32_t)(val * 4095.0f / 3.3f)` | `(uint32_t)(val * 1240.909f)` |
| `baud = 19200` | `baud = 1200 * 16` |
| `timer_prescaler = 240 - 1` | `timer_prescaler = 239` |

### 7.3 位操作重写

**原始：**
```c
val = (data[0] << 8) | data[1];
```

**新：**
```c
val = (u16)data[0] * 256u + data[1];
```

## 十、禁止修改项（保持兼容的底线）

以下内容**绝对不能改变**，否则赛题评估不通过：

1. **Flash 布局地址**（0x08000000、0x08010000、0x08011000 等）
2. **默认波特率 19200**
3. **RS-485 引脚**（PA2=TX, PA3=RX）+ 方向控制引脚
4. **固件版本号** v2.0.1.0（字节 `02 00 01 00`）
5. **协议帧格式**（A5B6 起始、B6A5 结束、字段顺序、CRC16-Modbus）
6. **所有 30+ 命令码** 和对应的响应格式
7. **ADC/DAC/OLED/SPI/I2C 的 GPIO 引脚分配**
8. **中断向量表偏移**（VTOR = 0x08011000 for APP）
9. **心跳帧格式和发送时机**
10. **自动上报帧格式**（12 字节 = UTC + CH0 + CH1）
11. **告警字符串格式**（`时间|CHx|阈值|实际值`）
12. **BootLoader OTA 协议**（魔术字 5AA5C33C、流格式、握手流程）
13. **GD32F4xx 标准外设库 API**（不可修改库函数本身）
14. **Keil 工程编译选项**（优化级别、宏定义等需保持一致）

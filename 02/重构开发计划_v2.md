## 一、"四个核心文件"修改计划（重中之重）

参考 `0000 core` 的四份核心文件模式，这4个文件是任何GD32工程的骨架：

| # | 核心文件 | 作用 | 当前02/路径 |
|---|---------|------|------------|
| 1 | `main.c` + `main.h` | 程序入口+主循环 | `System/src/main.c` |
| 2 | `systick.c` + `systick.h` | SysTick 1ms定时 | `System/src/systick.c` |
| 3 | `gd32f4xx_it.c` + `gd32f4xx_it.h` | 中断服务程序 | `System/src/gd32f4xx_it.c` |
| 4 | `gd32f4xx_libopt.h` | 库文件选择 | `HeaderFiles/User/` |

### 1.1 main.c 改造方案

**赛题要求检查清单：**
- [x] `SCB->VTOR = 0x08011000`（APP偏移地址）
- [x] `systick_config()` 初始化
- [x] 所有外设初始化 `System_Init()`
- [x] 上电15秒内发送心跳帧
- [x] `while(1)` 主循环：帧解析 + 自动上报 + LED心跳
- [x] `fputc()` 重定向printf到RS-485

**改造项：**

| 改造点 | 原始方式 | 新方式 |
|--------|---------|--------|
| 初始化函数名 | `bsp_led_init()`, `bsp_usart_init()` 等 | `Drv_LedInit()`, `Drv_UsartInit()` 等 |
| 主循环调度 | `scheduler_run()` | 直接在main()中按标志位轮询 |
| 系统初始化 | 分散调用7-8个init | 封装为 `Core_SystemInit()` 单函数 |
| 变量命名 | `g_led_toggle_flag` | `g_FlagLedToggle` |
| 版权头 | GigaDevice / MCUSTUDIO | `/* SPDX-License-Identifier: MIT */` |
| 注释语言 | 中文 | 全英文 `/** */` JavaDoc |

**新 main() 伪代码：**
```c
int main(void)
{
    SCB->VTOR = APP_FLASH_BASE;     /* 0x08011000 */
    Core_SystemInit();              /* systick + 所有外设 + 参数加载 */
    Core_SendHeartbeat();           /* 上电首帧心跳 */

    for (;;) {
        Proto_Poll();               /* 帧解析 + 命令分发 */
        AutoRpt_Poll();             /* 自动上报调度 */
        Led_Poll();                 /* 系统指示灯心跳 */
        Alarms_Poll();              /* 告警检测 */
    }
}
```

### 1.2 systick.c 改造方案

**赛题要求：** SysTick 提供 1ms 时基，用于 `delay_ms()` 和 `get_tick_ms()`

**改造项：**

| 改造点 | 原始方式 | 新方式 |
|--------|---------|--------|
| 函数名 | `systick_config()` | `Tick_Setup()` |
| 延时函数 | `delay_1ms(count)` | `Tick_DelayMs(count)` |
| 递减函数 | `delay_decrement()` | `Tick_Decrement()` |
| 获取毫秒 | `get_system_ms()` | `Tick_GetMs()` |
| 静态变量 | `delay` | `m_TickCounter` |
| 全局tick | 无 | `volatile uint32_t g_SysTick` — ISR中递增 |

**关键改进：**
- 增加 `g_SysTick` 累加计数器，`Tick_GetMs()` 返回当前毫秒
- `Tick_DelayMs()` 改为基于 `g_SysTick` 的超时判断（不阻塞其他ISR）
- 优先级保持 `NVIC_SetPriority(SysTick_IRQn, 0x00U)`

### 1.3 gd32f4xx_it.c 改造方案

**赛题要求涉及的ISR：**
- `SysTick_Handler` — 调用 `Tick_Decrement()` + `g_SysTick++`
- `USART1_IRQHandler` — RS-485数据接收 + IDLE中断
- `USART0_IRQHandler` — CH340调试接收（可选）
- `RTC_WKUP_IRQHandler` — RTC唤醒
- `EXTI0_IRQHandler` — 唤醒按键

**改造项：**

| 改造点 | 原始方式 | 新方式 |
|--------|---------|--------|
| 版权头 | GigaDevice BSD-3 | `/* SPDX-License-Identifier: MIT */` |
| 注释风格 | `/*! \brief ... */` | `/** @brief ... */` |
| SysTick | `delay_decrement()` | `Tick_Decrement()` + `g_SysTick++` |
| 全局变量命名 | `rxbuffer[]`, `rx_flag` | `g_RxBuf[]`, `g_FlagRx` |
| 缓冲区大小 | `OTA_UART_RXBUF_SIZE` | `RS485_RXBUF_SIZE` |

**关键：RS-485 方向控制时序不能改**
```c
// USART1_IRQHandler 中的核心逻辑（必须保持原有时序）
RS485_DIR(1);    // 发送模式
usart_data_transmit(...);
while (!(USART_STAT0(USART1) & USART_STAT0_TC));  // 等待发送完成
RS485_DIR(0);    // 接收模式
```

## 七、Bootloader 专项改造（N模块，18分）

### 7.1 OTA完整流程

```
APP 收到 0x0501 →
  ① 回复 OK 帧
  ② oled_printf("Bootloader")
  ③ 写入 upgrade_flag=0xA5 至参数区
  ④ NVIC_SystemReset()

Bootloader 启动 →
  ① 读参数区 upgrade_flag
  ② 若=0xA5：进入升级模式
     打印 "wait for start Application(10s)..."
     10s倒计时 → 7s → 4s → 1s
     期间收到 0x0502 → 准备接收固件
     超时无指令 → 跳转APP
  ③ 若≠0xA5：正常启动，5s后跳APP

Bootloader 接收固件 →
  ① 收到 0x0502 → 回复OK
  ② 接收bin文件切片(256B/片)
  ③ 校验魔术字 5AA5C33C → 错则回复 FF EEEE
  ④ 写入暂存区 0x08051000
  ⑤ 收到 0x0503 → 执行升级
  ⑥ 从暂存区搬运至APP区 0x08011000
  ⑦ 校验 → 跳转APP

升级后APP验证 →
  APP不应再响应 0x0501（N-03得分点）
```

- RS-485方向控制引脚必须与APP一致
- 默认波特率 19200
- OTA完成后APP不应解析升级命令

## 八、参数区 Flash 持久化方案

### 8.1 参数区布局（0x08010000，4KB）

```c
typedef struct {
    uint32_t magic;           // 0x43494D43 ("CIMC")
    uint32_t version;         // 0x00010001
    uint16_t device_id;       // 设备ID（默认0x0001）
    uint8_t  baud_code;       // 波特率编码（0x13=19200）
    uint8_t  alarm_mode;      // 告警模式（0x01=主动，0x02=静默）
    float    ch0_ratio;       // CH0变比（默认1.0）
    float    ch1_ratio;       // CH1变比（默认1.0）
    float    ch0_threshold;   // CH0阈值（默认3000.0）
    float    ch1_threshold;   // CH1阈值（默认3000.0）
    float    ch2_threshold;   // CH2/PT100阈值（默认80.0）
    uint8_t  upgrade_flag;    // OTA升级标记（0xA5=需要升级）
    uint8_t  reserved[47];    // 保留
    uint32_t crc32;           // CRC32校验
} ParamBlock_t;  // 总大小 = 80字节
```

### 8.2 告警持久化（0x08071000，4KB）

```c
typedef struct {
    uint32_t timestamp;       // UTC时间戳
    uint8_t  channel;         // 通道号(0/1/2)
    float    threshold;       // 阈值
    float    value;           // 实际值
} AlarmRecord_t;  // 每条13字节

#define ALARM_MAX_COUNT  10
#define ALARM_AREA_SIZE  4096
// 存储方式：10条记录 + CRC32
```

### 8.3 Flash写保护策略

- 写前检查内容是否相同 → 相同则跳过（减少Flash磨损）
- 参数区写前擦除整个4KB页
- 写入后立即回读校验
- 使用双页翻转（A/B页）防止写入途中掉电损坏

## 十一、禁止修改项（功能底线）

1. Flash地址布局（0x08000000、0x08010000、0x08011000等）
2. 默认波特率 **19200**
3. RS-485引脚 PA2(TX)/PA3(RX)
4. 固件版本号 v2.0.1.0（字节 `02 00 01 00`）
5. 协议帧格式（A5B6起始、B6A5结束、字段顺序）
6. 全部30+命令码及其响应
7. 心跳帧格式（A5B6 DDDD 05 8888 00 02 XXXX B6A5）
8. 自动上报12字节帧（UTC+CH0+CH1 IEEE754 BE）
9. 告警格式：`2026-01-01 HH:MM:SS | CHx | threshold | actual\r\n`
10. GPIO引脚分配（ADC/DAC/OLED/I2C/SPI）
11. OTA魔术字 `5AA5C33C`
12. GD32F4xx标准外设库API
